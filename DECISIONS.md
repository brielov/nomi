# Decisions

One dated paragraph per decision that would be expensive to reverse. If a decision can be a test, it is a test instead.

**2026-10-07: test support is a dev-only crate.** Parity ratchets are checked from each crate's own tests, so the ratchet code must be shared between crates. It lives in `nomi-testkit`, which any crate may take as a dev-dependency and none as a normal one; `xtask ci` enforces both. The alternative, running every suite through `xtask`, would put compiler APIs behind a process boundary for no gain.

**2026-10-07: corpus claims are per Compat.** Upstream accepts an application only when its `elm-version` equals the compiler's version, and a package only when its range admits it; the pinned apps all say 0.19.1 and 14 corpus packages exclude 0.19.3. So exit criteria that say "every corpus package/app/project" (M5, 6.7, 7.4, 7.5, 8.10) now mean every one the Compat accepts, with the rejected ones kept as expected-failure cases whose diagnostics must match (plan 1.15a). Oracle sandboxes rewrite app `elm-version` to the Compat under test. The alternative, pinning only projects every Compat accepts, would drop the apps from 0.19.2 and 0.19.3 entirely.

**2026-10-07: elm columns count code points, and the release decides the rest.** Probes with `é` and `😀` before a syntax error put the error at the same column in 0.19.1, 0.19.2 and 0.19.3, which counts code points, not UTF-8 bytes or UTF-16 units. A CR doesn't advance the column. 0.19.2 prints rows and columns from 0 where the others start at 1. 0.19.1 keeps rows and columns in 16 bits, so its parser sees a token at 1-based column 65,536 at column 0 and rejects three corpus modules with lines that long; the later releases accept them. So the validation pass takes a `Compat` along with the project kind, and regions will too (plan 4.4). The alternative, one column model for every release, would misjudge those modules for one release or the others.

**2026-10-07: modules parse in two layouts.** elm wants every continuation token right of its construct; elm-format checks indentation only before arguments and when aligning blocks, so it takes a declaration body, a closing parenthesis or an operator at column 0. One grammar serves both: `Layout::Strict` parses as elm does, which also recovers well from broken code, and when that fails `Layout::Loose` parses again, demanding indentation only where elm-format does. A clean loose parse wins and records each unindented token it consumed, which validation reports for elm. An error file costs two parses. The alternatives were a separate elm-format grammar, which would double every later syntax change, or one loose parse, whose recovery from a missing `)` or `=` swallows the next declaration.

**2026-10-07: doc comments use a Cheapskate port.** elm-format parses doc comments with its own fork of Cheapskate, which disagrees with CommonMark on lists, code block ends, `@docs` lines and more, and what it parses decides both the printed comment and which code blocks are Elm. So `format/src/markdown/` ports the fork and upstream's Markdown printer, quirks included, and lowering parses each Elm code block into the formatter tree as declarations, then expressions, then a module, as upstream tries them. The alternative, pulldown-cmark, would need a correction layer for every divergence, and the corpus has hundreds of doc comments that would find them.

**2026-10-07: an empty non-Elm code block prints as a blank line.** elm-format crashes on a code block with a language other than `elm` and no text (`Data.Text.last: empty input`). nomi prints the fence around one empty line, as it does for any code without a final newline. The `nomi/code_fences` fixtures that elm-format crashes on cover it. The alternative, rejecting every module with such a block, would refuse modules elm accepts.

**2026-10-07: invariant breaks follow upstream until decided.** elm-format 0.8.8 itself breaks the formatter's invariants: it drops comments in the module header, can leave an exposing list unparseable, moves some comments and doc-comment Markdown on a second run (48 corpus modules), prints `\x` escapes as other code points, prints `{-- }…-}` as a comment that ends at `{--}`, can unbalance a comment nested in a doc comment, which then swallows or exposes code, reflows `(f x) y` and `[a..b] y` spanning lines differently on a second run, prints an Elm 0.18 infix declaration that a comment spreads over lines as a request to report it, exposes both a type alias and a type of one name in a module without a header, as `Y(..), Y`, where a second run exposes `Y(..)` alone, and prints a float too large for a double as `Infinity`, a name Elm doesn't define. Each nomi break on the fixtures, the corpus and the fuzzer's findings was checked to be upstream's, byte for byte, and is listed in an `invariants.tsv` beside the parity tables; property tests and the fuzzer allow only these classes (`upstream_breaks`). Parity stays the default, and 2.15 turns each class into a fixed deviation or keeps it. The alternative, fixing them during 2.14, would mix deviations into the parity work before the corpus says which ones matter.

**2026-10-08: comments the docs move stay inside the exposing list.** When `@docs` reorders the exposing list, elm-format gathers the comments of the items it moved after them, joined like an item, so a one-line list ends `(x, y, {- c -})`, which doesn't parse. nomi prints them after a space, `(x, y {- c -})`, which a second run reads back the same; a list spanning lines already stacks them before `)` and stays as upstream. The `nomi/export_comments` cases under `format_fixtures/deviations/` cover it. With this, formatting a module with comments must keep it parseable, which the invariant checks now hold it to. The alternative, attaching the comments to the last item, would also move them in the lists that span lines, where upstream's output is fine.

**2026-10-08: a `{--` comment keeps the space that keeps it one comment.** elm-format drops the spaces after `{--` and before `-}`, so `{-- } a -}` prints as `{--} a-}`, a comment that ends at `{--}` and leaves the rest as code, and `{-- a { -}` as `{--a {-}`, whose `{-` opens a comment that never closes. nomi keeps one space before a leading `}` and after a trailing `{`, and spells every other `{--` comment as upstream does. The `nomi/trick_blocks` fixture covers it. The alternative, keeping all of the comment's spaces, would change the many `{--…-}` comments upstream prints fine.

**2026-10-08: a float too large for a double prints as `1.0e309`.** elm-format reads a float literal into a double and prints the overflow as `Infinity`, a name Elm doesn't define, so `1e999` formats to code that no longer compiles. nomi prints an infinite magnitude as the least power of ten that reads back as infinite: `1.0e309` where upstream would use an exponent and `1` with 309 zeros and `.0` where it would write the digits out, with the sign in front as upstream. Elm keeps a float literal's text for JavaScript, which reads both as `Infinity`, so the meaning holds and a second run prints the same. The `nomi/large_floats` fixture covers it. The alternative, keeping the literal as written, would need the formatter's tree to carry source text for every float to serve a case that only overflowing literals reach.

**2026-10-08: a doc comment whose reprint would end elsewhere stays as written.** elm-format reprints a doc comment from its Markdown, which can undo the nesting of a comment inside: a code block's info string keeps only its first word, so ```` ```elm {- a ```` loses the `{-` that a later `-}` closes, and the reprinted comment ends early or swallows the code after it. nomi lexes the reprinted comment and, unless it is one doc comment, prints the comment as written, without trailing whitespace. The `nomi/doc_comment_nesting` fixture covers it. The alternative, repairing the Markdown, would mean guessing which of the comment's parts the author meant as code; keeping it as written is what they had and stays parseable.

**2026-10-08: the remaining invariant breaks stay upstream's.** 2.15 deviates where elm-format's output of code Elm accepts doesn't parse or reads differently: comments the docs move into a one-line exposing list, `{--` comments that end early or never close, floats too large for a double, and doc comments whose reprint ends elsewhere. The other breaks stay as elm-format makes them. Comments it drops from the module header, comments and doc-comment Markdown that move on a second run, and `(f x) y` or `[a..b] y` reflowing on a second run all leave code that compiles to the same program, and changing them would move nomi's first run away from elm-format's on all 48 corpus modules they reach. `\x` escapes, Elm 0.18 infix declarations printed as a request to report them, and a module without a header exposing `Y(..), Y` arise only from code Elm 0.19 rejects, so there is no meaning to keep. `upstream_breaks` lists these five classes, and the `invariants.tsv` tables the modules that reach them. The alternative, making nomi idempotent everywhere, would trade parity on modules people format today for a second run they rarely make.

**2026-10-08: a negated negation keeps its parentheses.** elm-format drops the parentheses around a negation's operand when the operand needs none, so `-(-x)` prints as `--x`, which starts a comment that swallows the rest of the line. nomi keeps the parentheses when the operand prints starting with `-`. A negated zero stays upstream's: `-(0)` prints as `-0`, which a second run reads as `0`, the same number. The fuzzer found both through `1 -(1e2)`, which prints as `1 -1.0e2`, one negative literal where the source had a negation; the token check now reads both alike.

**2026-10-08: elm-format's command line deviates where its output depends on chance.** Invoked as `elm-format`, nomi parses elm-format 0.8.8's arguments as its optparse-applicative parser does and repeats its prompts, messages, `--validate` JSON and exit codes byte for byte; `crates/cli/tests/elm_format/` holds the cases and elm-format's transcripts. It differs in five ways. A directory's modules come in the order of their names, where elm-format takes the order the disk lists them in, and the modules it formats at once report in the order they were named, where elm-format's threads interleave. A file that isn't UTF-8 is a syntax error at its first bad byte and stays as it was, where elm-format reads replacement characters and can write them back. Files are replaced in one step, and an I/O failure is reported for its file while the others go on, where elm-format writes in place and dies at the first failure. `--elm-version` 0.17 and 0.18, and a project elm-format would take for 0.18, exit with one line saying nomi formats 0.19 only (`deviations/` covers them). The internal `--json` and `--from-json` flags are unknown options. Syntax errors are reported where elm-format's parser stops, from a port of it (the entry on elm-format's syntax error positions). The alternative, reproducing disk and thread order, would make every run's output depend on the machine, which no caller can rely on today either.

**2026-10-08: the 0.19.1 solver oracle is built from 0.19.2's sources.** The solver oracle compiles upstream's `Deps/Solver.hs` with the GHC 9.14.1 that D3 pins. 0.19.1's sources don't compile with it (`Data/Utf8.hs` mixes `Word#` and `Word8#`), and GHC 9.8, which D3 allowed as the fallback, is past GHC 9.2's split of the two, so it fails the same way. So 0.19.1's oracle is 0.19.2's sources with `Paths_elm` saying 0.19.1, which sets `V.compiler`. Between the two tags, `Deps/Solver.hs` differs only in how decoding threads through IO, and `Elm/Outline.hs` and `Elm/Constraint.hs` only in parser plumbing, so the search and the `elm-version` checks are 0.19.1's. The alternative, an older GHC with an older package set, would put a second toolchain on every machine that records snapshots, for code that doesn't differ.

**2026-10-08: upstream's search selects, PubGrub explains.** nomi must pick the versions upstream's `Deps/Solver.hs` picks: pending packages in name order, versions newest first, depth first, the first solution found. PubGrub with name priority and newest-first versions agrees with that on every 3.6 scenario, but not in general: over 200,000 random registries it picked differently 24 times when dependencies could form cycles and 79 times when each package depended only on earlier names, because conflict learning backjumps past choices the plain search would revisit. Scenario `pubgrub-differs` is one of those registries, and upstream answers as the port does. So `registry::solver` is a port of upstream's search, and `solver::explain` runs PubGrub over the same releases only once that search has found nothing, to say why. The two can't disagree on whether a solution exists, which a test checks. The alternatives were PubGrub alone, which would change what `install` writes, or the port alone, which can only say "no solution". (2026-10-16 below drops the explanation.)

**2026-10-08: `install` changes elm.json and downloads, but doesn't build.** Invoked as `elm`, `init` and `install` repeat elm's prompts, plans, `elm.json` edits and reports byte for byte; `crates/cli/tests/elm/` holds the cases and elm's transcripts. Upstream's `install` goes on to build every dependency and reports a build failure as an install failure; nomi checks the new dependencies, downloads them into its store, and leaves building to the builds that need it (milestone 4), so a package that downloads but doesn't compile installs fine. When that check fails nomi writes back the original bytes of `elm.json`, where upstream re-encodes the outline it read, which can change the file's spacing. INSTALL WHAT? names nomi's package store where elm names `ELM_HOME`, so its hint wraps differently, and an engine test covers it instead of the transcript. HTTP failures say less than upstream's, since nomi's client keeps no response headers or bodies. nomi takes no lock on the project, as elm does around `install`, until builds share a project (milestone 4). The alternative, building during `install`, would need milestone 4's build graph inside a step of milestone 3.

**2026-10-08: `rm` keeps the versions it has.** Upstream has no `remove`, so `nomi rm` (alias `remove`) is nomi's own, with messages in `install`'s style. It doesn't call the solver: an application keeps its direct dependencies but the one removed, and its indirect and test dependencies become what the remaining ones reach through the releases already in `elm.json`, at those versions. So `rm` never upgrades or downgrades anything, never needs a solution that might not exist, and undoes an `add` that only inserted packages, byte for byte, which `removing_undoes_adding` checks over the solver scenarios and a CLI test checks through `add` and `rm`. A package loses the one constraint. An indirect dependency can't be removed on its own; the report names what needs it. The alternative, re-solving for the remaining dependencies, would pick the newest versions and so turn every removal into an upgrade the user didn't ask for.

**2026-10-08: `update` stays within major versions.** Upstream has no `update`, `outdated` or `tree`, so they are nomi's own. `nomi update` lets each of an application's direct and test dependencies move up to its next major version, which keeps its API, and re-solves what they need with upstream's search, so it picks what `install` would. `update <package>` frees only that package and the dependencies that need it; the rest are held exactly, and if that fails only the other direct ones are. `updating_stays_within_majors` checks over the solver scenarios that no direct dependency moves back or across a major version, that elm accepts the result, that a second update changes nothing, and that one package's update moves only what needs it. A package's elm.json holds ranges, which every build already resolves to the newest releases they allow, so `update` there writes nothing. `outdated` reads the index only: an application's direct dependencies with newer releases, and a package's with releases past its ranges. The alternative, letting `update` cross major versions, would rewrite code's dependencies under it; that belongs in a separate, explicit command if anyone asks for one.

**2026-10-08: snapshots freeze the editor's text, not the disk.** A `Snapshot` of the `Vfs` shares the overlays as they were at its revision, so an edit never changes text under a reader. It reads the disk when asked instead of copying it: copying every file a build might read would cost what reading it does, and the disk can change without nomi knowing anyway. Instead, every write nomi makes, and every change a watcher reports through `disk_changed`, makes a new revision, which marks older snapshots stale so their work stops between phases and starts again (architecture §6). A `FileId` comes from the path with every symbolic link resolved; of a file not on disk yet, an editor's unsaved buffer, the longest part that exists is resolved and the rest taken lexically. On macOS this also folds a path's case to the disk's. Ids are never reused, so a path keeps its id for the life of the `Vfs`.

**2026-10-08: the module graph finds upstream's first cycle, except where 0.19.3 crashes.** `engine::graph` crawls as `Build.hs` does and orders modules per release, by bytes in 0.19.1 and 0.19.2 and by length then bytes in 0.19.3, because that order chooses the cycle reported when there are several. 0.19.1 and 0.19.2 report the whole first component; 0.19.3 reports the shortest cycle through its first module. Default imports are part of the graph, as upstream crawls them; leaving them out changes which component comes first. A model of this was compared with all three elm releases over 100 random graphs, with no differences. There is one deviation. When the first module of 0.19.3's component imports itself, `withMinimalCycle` reads outside its array, and elm crashes or hangs; nomi reports that module alone, as the older releases do. A module that isn't UTF-8 is parsed as its bytes, as upstream parses it, and shown with a replacement character for each run of bad bytes (plan 7.6); 0.19.1 dies on most of these, and nomi reports them as it reports them for the later releases. The alternative, Tarjan's algorithm or any order of nomi's own, would report another cycle than elm's on the same project.

**2026-10-08: a damaged artifact is a miss, and the cache trims like Go's.** `engine::artifacts` keeps what builds make in one per-user directory, each entry filed under a SHA-256 of everything its build read: the kind, nomi's version, and the named, length-prefixed parts the caller adds (source, `Compat`, imports' interface hashes, package). An entry repeats its key and its payload's length and hash, as the first attempt's did, and any entry that doesn't check out is read as a miss and replaced by the next build. The first attempt failed the build instead, which turns a disk fault or a killed write into an error the user must clear by hand, for a cache whose whole contract is that it can be rebuilt. Trimming follows `GOCACHE`: reading an entry refreshes its time at most hourly, and at most daily the entries unused for five days are removed, so the cache needs no size setting and no command to clean it. The scheduler runs the module DAG with a counter per module rather than in waves, so a slow module holds up only what imports it; the outcomes come back in the modules' order whatever order they ran in.

**2026-10-08: snippets show positions as each release keeps them.** 0.19.1 keeps rows and columns from 1 in 16 bits, and 0.19.2 and 0.19.3 from 0 in 32. Most snippets hide this, since `viewLineNumber` adds the 1 back, but `Code.toPair` on one row prints the row as kept, so from 0.19.2 on the first line of a file shows as `0|`. nomi repeats it, and wraps 0.19.1's rows and columns past 65,535 as upstream does. `--report=json` regions count from 1 in 0.19.1, from 0 in 0.19.2, and from 1 again in 0.19.3, which adds 1 for editors. Documents name the code they show by byte range, and `code::expand` puts in the lines for one release just before layout, so a diagnostic holds no source text and renders for any release. Text and JSON match elm's output in all three releases for one-row and two-row pairs, a region over rows, and a tab in the source. Where upstream fails, on a snippet with no lines or a pair on a row past the end, nomi shows an empty line. The alternative, rendering snippets when a phase reports them, would tie every diagnostic to one release and to its file's text.

**2026-10-08: elm.json reports are upstream's, except where upstream hangs or dies.** `nomi_project::report` ports `Reporting/Error/Json.hs` and the outline half of `Reporting/Exit.hs`, and `nomi_registry::report` the details and package halves, so every command that reads a project reports a broken `elm.json`, a hand-edited dependency set or a corrupt download as elm does. `cargo xtask oracle outline` records each release's `--report=json` for 41 broken fixtures, and `tests/reports.rs` compares nomi's 472 reports with them byte for byte; transcripts cover the reports about more than the file. nomi deviates in five places. `expectationToReport` defines the region of a value on one row as itself, so upstream hangs after the first paragraph; nomi underlines the value, and a value over rows shows its first position, as upstream does. 0.19.1 counts the rows before a parse error in 16 bits, so an error on the first row starts at row 65,535 and dies; nomi starts at the first row, as later releases do. 0.19.1 also dies on a string byte that can't start UTF-8, which nomi reports as UNEXPECTED ENCODING, as later releases do. 0.19.1's details reports suggest "the dependency management tool in elm reactor" only when invoked as `elm`, since nomi has no reactor. A store that can't be read or written gets a report of nomi's own, since upstream's store has no such failure. Missing source directories are checked on disk, not in the `Vfs`, which tracks files only, and redundant ones by their canonical paths, compared as strings so the pair reported is upstream's. The alternative, repeating upstream's hangs and crashes, would leave a user with no report at all.

**2026-10-08: elm's syntax errors come from a port of its parser.** elm's title and region for a syntax error depend on where its backtracking parser gives up and on every context it unwinds through: which alternative of a `oneOf` consumed input, where each `inContext` started, and whether `Space.chomp` had run, which counts as consuming input even when it eats nothing. nomi's grammar recovers and resynchronizes, and its first error agrees with elm's position on about two thirds of the mutation suite. So `nomi_syntax::elm` ports `Parse/*.hs` and the error types of `Reporting/Error/Syntax.hs`, one parser for every release with 0.19.1's 16-bit, 1-based rows and columns behind its `Cursor`, and runs it only on a module the grammar rejects. It builds no tree and serves no other caller; the mutation suite holds it to rejecting exactly what each release rejects, so the two can't drift unseen. The alternative, teaching the recovering grammar to record upstream's constructors, would mean reproducing a backtracking parser's failure points in one that doesn't backtrack, case by case, across 29,511 rejected mutations.

**2026-10-08: elm-format's syntax error positions come from a port of its parser.** elm-format reports an unparsable module at the row and column where its Parsec-style parser's last error continuation ran, which depends on every `try`, `<|>` and `commitIf` it went through, on its own column counting (a tab to the next multiple of eight in `satisfy`, one column a character in the number and string primitives), and on 16-bit rows and columns that wrap. nomi's first error is at the same place on 64% of the mutation suite's rejected cases. So `nomi_syntax::elm_format` ports elm-format 0.8.8's `Parse/*.hs` for 0.19 syntax, over its `ParsecAdapter` semantics, and `format_text` reports its position when nomi's grammar rejects a module, falling back to nomi's own where the port accepts or crashes. Like the port of elm's parser, it builds no tree, returning only what upstream's control flow reads back: whether a pattern is a variable, and whether a parenthesized pattern had comments. The mutation suite holds it exact on all 27,814 rejected cases. Where elm-format itself crashes (`satisfy` on U+FFFE or U+FFFF, `many` over a parser that accepts nothing) the port says so, and nomi reports its own position rather than crash. The alternative, recording elm-format's position in nomi's recovering grammar, would mean reproducing a second backtracking parser's failure points in one that doesn't backtrack.

**2026-10-08: a syntax error report is a `Problem`, not a `Diagnostic`.** `nomi_syntax::elm::to_problem` ports `Reporting/Error/Syntax.hs` from the constructors of the port of elm's parser, a part per plan step, and gives a `diagnostic::Problem`: a title, a region and a message, which writes elm's `--report=json` problem for a release. A `Diagnostic` names its code by byte range and expands it for any release, but a syntax error's region is made for one release: 0.19.1's columns wrap at 65,535 before the report reads them, upstream widens regions by counting characters past where it stopped, and it can point past the end of a line or the text. So the region stays in rows and columns, as the release's parser kept them, and `code::Source::what_is_next` repeats how upstream reads the text at a position, including two quirks: it drops `col - 1` characters in every release, so from 0.19.2 on, where columns start at 0, it looks one character early; and a lower-case name's region spans the whole name plus its first letter, as `Lower c name` holds the whole name. Two ratchets over the mutation suite hold the port to elm's titles and regions (`syntax_titles`) and to the hash of its whole JSON report (`syntax_reports`). The alternative, a byte-range `Diagnostic`, would need a range for a position upstream computes past the text, and would lose 0.19.1's wrapped regions.

**2026-10-08: nesting past 25,000 levels is an error elm doesn't have.** nomi's grammar gives up past `DEPTH_LIMIT` (25,000) nested rules, because rowan builds and drops trees recursively and `nomi_base::STACK_SIZE` is sized for the deepest tree the limit admits. elm has no limit, and neither has nomi's port of its parser, `elm::parse`, which grows its stack as it goes. So a module that only nomi rejects gets nomi's own report, `TOO MUCH NESTING`, and a disagreement of any other kind gets a `SYNTAX PROBLEM` report that says it is nomi's bug, never no report at all. A shader nested that deep is a `SHADER PROBLEM` with an empty message where elm accepts it, the same limit in the GLSL recognizer. The alternatives were trees that drop iteratively and no limit, which would touch every phase that walks a tree, or skipping the module, which would hide the failure.

**2026-10-09: imports of one module stay apart where merging loses a used qualifier.** elm-format merges every import of a module into one, keeping the later alias, so `import Html` and `import Html as H` become `import Html as H`. Elm gives each import its own qualifier, so a module that writes `Html.text` stops compiling. The HIR invariant (plan 5.15) found 21 corpus modules where this happens. nomi merges as elm-format does wherever the qualifiers the merge drops go unused, and otherwise keeps the import apart, after the merged one. Its exposing list stays with it. The fixture `nomi/import_qualifiers` has a deviation file, and `corpus/format/deviations.tsv` holds nomi's output for the 21 modules, each checked to differ from elm-format's in import lines alone. The alternative, keeping elm-format's merge, would format working code into code that doesn't compile.

**2026-10-09: a module without a header that declares ports gets a port module line.** Elm reads a module without a header as a port module when it declares ports (`checkModule`). elm-format gives every module without a header the line `module Main exposing (…)`, and with ports Elm rejects that line. nomi writes `port module Main exposing (…)` there instead. The HIR invariant (plan 5.15) found it on elm-format's own fixtures `Ports`, `PortsWithTypeAliases` and `ExplicitlyListExposedValues`, which have deviation files differing only by the `port` keyword; no corpus module has a port without a header. The alternative, elm-format's line, would format a module Elm compiles into one it rejects.

**2026-10-09: the HIR invariant joins the token check rather than replacing it.** Plan 5.15 meant the check that formatting leaves a module's HIR unchanged to replace 2.14's token check. But `nomi-format` may depend only on `base` and `syntax` (architecture §4), and the HIR is the compiler's. So the token check stays in `nomi_format::broken_invariants`, where the formatter's property tests and fuzzer use it. The HIR check is `nomi_engine::format::shape_change`, where both crates meet; the engine's `format_shape` test runs it on the formatter's fixtures and the compiler's packages, and `cargo xtask corpus hir` on every corpus module Elm accepts. It compares shapes as Elm reads them (`nomi_compiler::hir::shape`). One break stays upstream's, decided so: elm-format reads a CRLF line break in a multiline string as `\n`, where Elm keeps the carriage return, which changes the string in 9 corpus modules (elm-mustache, elm-dnn-http). elm-format's own `WindowsEol` fixture shows it does this on purpose, and keeping the `\r` would print `\u{000D}` in every multiline string of a CRLF file, where the carriage returns came from the editor's line endings rather than from anyone's intent. `shape_change` allows it in a module with such a string. The alternative, letting the format crate depend on the compiler, would make the formatter build with the type checker and break the crate table.

**2026-10-09: navigation reads packages from the store, never the network.** An editor asks for a definition many times a minute, so `nomi_engine::index` takes each dependency's sources from the package store as they are. An application's are the releases its `elm.json` pins. A package declares ranges, which only the solver and the registry resolve, so its dependencies are the newest releases the store holds in each range, which `nomi check` or `nomi add` downloaded. A dependency the store lacks is left out, and names from it go nowhere; the project's own modules navigate all the same. The alternative, solving and downloading as `nomi check` does, would make a definition request wait on the network and fail offline.

**2026-10-11: dependency progress is compared as one step.** In the terminal style, elm prints `Verifying dependencies (k/n)` as its threads report packages found and built, and how those reports interleave varies between runs of one elm, even with one capability: the matrix's recordings hold `(1/2)(2/2)`, `(0/2)(1/2)(2/2)` and others for the same case and release. So the `elm_make` ratchet reads a run of those steps as one step to `n`, in elm's transcripts and nomi's alike; nomi prints `(0/n)` through `(n/n)`. **2026-10-12: the language server reports elm's own diagnostics as you type.** elm-language-server 2.10.0 checks code twice: on every change with a type checker of its own, which approximates elm's and reports in its own words (`type_mismatch` and 28 more), and on open and save with `elm make --report json`. nomi has elm's checker, so its server reports the compiler's diagnostics on every change, in elm-language-server's shape for `elm make` results: source `Elm`, its message form, and the `data.code` its code actions key on (`missing_value`, `import_resolve`, `incomplete_case_pattern`, `record_field`, `missing_type_annotation`). **2026-10-12: lint rules read a broken file as nomi's parser recovers it.** elm-language-server's lint rules are tree-sitter queries, so in a file with a syntax error they see whatever tree-sitter-elm made of the broken part: sometimes nothing past it, sometimes a variable named `exposing` or one with no name. nomi runs the same rules over the tree its own parser recovers, skipping only imports that didn't parse whole. **2026-10-12: references are where code names it.** elm-language-server counts its default imports (`import List exposing ((::))`, `import Platform.Cmd as Cmd exposing (Cmd)` and the rest) as written at the top of every project file, so references to `String`, `List`, `Cmd` and the values and types they expose include a location in each file, at the line and column where that virtual import would sit: line 5, column 7 (from zero) for the module `String`, column 24 for the type it exposes. **2026-10-13: a pattern's variables have all their uses.** elm-language-server finds the uses of a variable a `case` branch or a lambda binds by climbing a fixed number of nodes from it in tree-sitter-elm's tree, three for a branch and two for a lambda, and searching what it lands on. **2026-10-13: `nomi test` is elm-test's command line.** `nomi test` takes elm-test's options and globs and prints what elm-test prints, its help and messages naming elm-test included, as the runner's own Elm reporters do in any case (`To reproduce these results, run: elm-test …`). **2026-10-14: upstream's reports and the editor's problems are two models.** The architecture first planned one diagnostic model, with a stable code, spans, a message and fixes, rendered to the terminal, to `--report=json` and to the language server. base had its types, but nothing ever built one: elm's reports are `Report` and `Problem`, whose regions are kept as each release keeps positions (2026-10-08 above), and the language server's problems are ide's own, shaped as elm-language-server publishes them: a byte range in a file, the message on one line, a source and a code its code actions key on, a path relative to the project, and elm-review's edits. **2026-10-15: Node replaces elm/core's Scheduler, not its Platform.** R1 lists `Platform` among the kernels Node overrides, for the process lifecycle. **2026-10-15: `nomi test` runs its runner on Node's kernels, with the DOM's.** elm-test's runner is a `Platform.worker` it runs in Node, with stand-ins for the browser's globals that let tests build `Html` and reach the `VirtualDom`, `Browser` and `File` kernels, which two of the corpus suites do. nomi builds that runner for Node, so it runs on the fiber runtime and Node's Scheduler, but with the DOM's kernels available (`Dom::Polyfilled`), where a Node program of the user's has them refused (R1). **2026-10-15: elm/http on Node tracks only what it receives.** elm/http 2.0.0's kernel is replaced on Node by one on `fetch`, which gives the `Result`s upstream's XMLHttpRequest gives, but `fetch` reports nothing of a request body's upload. **2026-10-16: a failed solve says what upstream says.** The 2026-10-08 entry kept PubGrub to say why the ported search found no solution, but nothing ever showed what it said: every command reports a failed solve with upstream's fixed text for its case, which names no conflict. `install` gives CANNOT FIND COMPATIBLE VERSION (or its offline form), a build's dependency check INCOMPATIBLE DEPENDENCIES (`DetailsProblem::NoSolution`) or TROUBLE VERIFYING DEPENDENCIES offline, and `init` NO SOLUTION or NO OFFLINE SOLUTION; nomi's own `update` gives CANNOT FIND COMPATIBLE VERSIONS and `nomi test` NO SOLUTION FOR THE TESTS, in the same style. **2026-10-17: nomi's own packages are trusted for their bundle, not their name.** nomi bundles `nomi/*` and trusts their kernel code, as upstream's `Pkg.isKernel` trusts `elm/*` and `elm-explorations/*`. **2026-10-17: a program `nomi run` starts dies with nomi.** A Node program whose `nomi run` is SIGKILLed, crashes or loses its terminal ran on unwatched, holding its port and files. **2026-10-17: `nomi build` writes an entry without `output` to `dist/`.** An entry of `nomi.toml` with no `output` was written under `elm-stuff/nomi/run`, hidden in a directory people delete, so a build left nothing to deploy. `nomi build` now writes it to `dist/` in its project, named by its `main` (`dist/Main.mjs`, or `.js` for the browser), or by the `main`'s path where two entries' `main`s share a name. `nomi run` keeps `elm-stuff/nomi/run`: it writes DEV code, again on every change under `--watch`, which in `dist/` would replace what `nomi build --optimize` left there to deploy.

**2026-10-17: nomi has no FFI.** M11 shipped `Nomi.Ffi`, an entry's async JavaScript functions called by name with JSON in and a decoder out, to cover what the Node platform didn't. Elm has no FFI: effects come from the platform's own packages, with typed APIs, and packages are pure Elm, which is what lets a program be trusted from its types. An FFI undid that. A published package could call a function that each application had to supply under a name the types never mention, a capability such as `Fs.readOnly` meant nothing to JavaScript that could read any file, and `nomi/test`'s file system and clock could fake nothing it did. So `Nomi.Ffi`, its kernel, `--ffi` and nomi.toml's `ffi` are gone, and a key `ffi` is unknown, and what a backend needs is nomi's to provide as typed `nomi/*` modules, as Bun ships its drivers (plan MB). The alternative, an FFI only applications may use, as Elm allows ports only in applications, would still leave capabilities and tests open, and take away the pressure to design the APIs a backend needs.

**2026-10-17: nomi's server programs run on Bun only.** The backend platform needs a WebSocket server, Postgres, MySQL, SQLite, Redis, S3, argon2 and zstd. Plain Elm programs build for the browser as before. **2026-10-17: the server platform is named `bun`.** nomi.toml's `platform = "node"` and `--platform=node` named the host a server program runs on, and that host is now Bun, so the value becomes `"bun"`; `"node"` is UNKNOWN PLATFORM, and the report names `"bun"`. `nomi test` runs on Bun as programs do, a browser project's elm-test suite included, so testing with nomi needs Bun where elm-test needed Node; its output stays elm-test's, which the tests corpus suite checks on Bun. **2026-10-17: SQLite statements run on the event loop.** `Bun.sql` runs a SQLite statement synchronously: on Bun 1.4.3 a 400 ms query let no timer fire, and its `cancel` couldn't run until the query ended. **2026-10-19: HTTP on Bun follows Fetch's rules.** The server kernel moved from `node:http` to `Bun.serve`, whose requests and responses are Fetch's, so nomi/server reads and writes HTTP as Fetch does rather than as Node did. A header sent twice reads as its values joined with `, ` (`; ` for `Cookie`), where Node kept only the first `Content-Type`, `Authorization` or `Host`. A response whose status Fetch refuses, as 999, answers 500 as a header with a line break does. `respond` gives a response's headers as Fetch lists them, names in lower case and in order, each `Set-Cookie` apart. Bun also gives a request still running 10 seconds no more time, which the kernel turns off, so a request in flight is the handler's to answer however long it takes. elm/http's requests on Bun honour `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY`, which Node's ignored; the tests' blackhole proxy exempts this machine for that. The alternative, writing raw HTTP/1.1 on `Bun.listen` to keep Node's rules, would mean a parser of nomi's own, which MB rules out.

**2026-10-19: streams fail with `Stream.Error`, stdio included.** `Nomi.Stream`'s readers and writers are the standard streams too, so `Stdio.print` and `printLine` fail with `Stream.Error` as any write does, where they couldn't fail before: a program maps the error once, as it maps a file's. Writing to `stdout` and `stderr` still drops output a closed pipe refuses, so in practice those writes don't fail; `Nomi.log` stays a `Task x ()`. A reader made by a task runs it on a fiber of the fiber that made the reader, so the reader is that fiber's resource, as D6 has every handle be: once the fiber ends, reading fails with `Closed`. Its source runs only while a read waits, and a chunk it gives stays in the reader until a read is handed it, so an interrupted read loses nothing; the runtime's `waitHost` hands a host's chunk over before an interruption, as `wait` does another fiber's, while the test clock waits for it. Terminals are asked of either end: `isTerminal` and `size` of a writer, and `isInteractive` of a reader. The alternative, making `print` a `Task x ()` that swallows failures, would hide a socket or file write failing behind the same function.

**2026-10-19: files as streams are opened, not lent.** `Fs.reader`, `Fs.writer` and `Fs.appender` open a file as a `Stream.Reader` or `Writer` that the fiber which opened it owns: the file closes at the reader's end, on `Stream.close`, or once that fiber ends, however it ends. D6 named an `Fs.withFile` lending the stream to a task; its error type would have had to join `Fs.Error`, the task's own and `Stream.Error`, and running the task on a fiber of its own (`Nomi.Fiber.fork`, then `join`) narrows the file's life the same way. `remove` takes `{ recursive }`, failing with `NotEmpty` on a directory that holds anything without it, `Fs.read` fails with `NotUtf8`, and a `Stat`'s time is the program's clock in memory, so a test's. `temporaryDirectory` makes a capability of its own that the fiber owns, removed with everything in it once that fiber ends, and only from a capability that may write. A symbolic link's target mustn't lead out of the capability or be absolute; one that does elsewhere, as on disk already, is refused when followed. A watch gathers the paths that changed, each once, until a `change` takes them, a thousand at most before it says only `"."`; the paths are hints, as the system's events are. In memory a file system resolves links as the disk does, so one table of cases checks both.

**2026-10-19: commands are the fiber's, and a stuck program says so.** `Nomi.Process` runs a command from a list, never a shell's string, through `env.processes`, a capability with a fake (`Process.fake`, whose `ran` lists what it ran with each command's input, and nomi/test's `withCommands`). A spawned child is the fiber's that spawned it (D6): once that fiber ends, a child still running gets SIGTERM, then SIGKILL once its grace passes, five seconds unless `withGrace` gives another, which the plan's design left unsaid. `output` runs in a scope of its own, so it ends its child no later than itself. A `Command` is opaque and read through `program`, `arguments` and `input`, since its input is `Bytes`, which `==` can't compare. `signal` gives a `Maybe`, `Nothing` once the listening fiber ended, as D6 has every event source do, where the design wrote `Task x Signal`. A program whose fibers all wait for one another, with nothing left that could wake one, used to exit 0 silently once the event loop emptied; the runtime now stops it as an exit with 1 would, saying it is stuck, and a fiber waiting for a signal keeps the process alive, so a program that only waits for SIGHUP isn't stuck.

**2026-10-20: nomi/http streams both ways.** nomi/server is nomi/http 2.0.0, its module `Nomi.Http.Server`, and a project still naming nomi/server gets PACKAGE RENAMED with what to ask for. A request's `body` is a `Stream.Reader` that fails with `TooLarge` past `maxBodyBytes` (at once when `Content-Length` says so), and `bodyBytes`, `bodyText` (refusing what isn't UTF-8) and `bodyJson` read it whole, so a body is read once; they are named apart from the responses' `bytes`, `text` and `json`. A streamed response is pumped by the request's own fiber, which Bun pulls from as the client takes what was sent, so a slow client holds back what produces the body and what the handler opened stays open until it is sent. Bun keeps a `Content-Length` only for a body whose first pull is all of it, so `file` sends Bun's own file, at the path the capability resolved, with its size and straight from the file, rather than a stream of it. Bun sends a streamed response's headers with its first chunk, so `events` opens with an SSE comment, which lets a client see the stream open before the first event and keeps idle proxies from closing it. TLS takes a certificate and key in PEM through `Config`, read however the program likes.

**2026-10-20: the client follows redirects itself, and a loopback is a network.** `Nomi.Net` holds the network capability `Env` carries: `onlyHosts` narrows it to hosts by name, a second narrowing only taking hosts away, and `noListen` refuses servers. `Nomi.Http.Client` sends with `fetch` but follows redirects itself, so each hop is a host the capability allows, and drops `Authorization` and `Cookie` when one leads to another host; a timeout is a deadline each hop's wait races, not a race around the whole send. `Net.loopback` is a network of its own in memory: a server listening on it is its handler, kept under its host and port, every name of this machine being one host, and a client sending on it runs the handler on a fiber of the sender's, so the sender ending, or the request timing out, is the client going away. A loopback's responses are the handler's, without the headers a connection adds, as `Date` and `Content-Length`; under `nomi test` they take no real time, so handlers that sleep or time out are tested on the test's clock.

**2026-10-20: a WebSocket is a fiber of its request's.** `Nomi.Http.Server.upgrade` makes the request's connection a WebSocket whose handler runs on a fiber of the request's: once it ends, the connection closes with 1000, and once the peer leaves, the fiber is interrupted, as a request's is when its client goes away, with `WebSocket.closed` telling a finalizer the code the peer closed with. `receive` takes messages in order and fails with `Closed` and the code once none are left; `send` waits for Bun's `drain` when Bun buffers it, so a peer that reads nothing holds the sender back. A client connection (`connect`) is the fiber's that made it, closed with 1000 once it ends. On `Net.loopback` the two ends are a pair in memory. Bun's client says only that a server didn't upgrade, not the status it answered, so `Refused` carries none, on a socket or a loopback alike. The server and WebSocket kernels refer to each other, which the kernels' globals allow since each refers to the other only inside functions.

**2026-10-20: a test's randomness is its own.** `Nomi.Random`'s values come from the system's secure source, but under `nomi test` from a generator on the test's runtime that its description seeds, so each effectful test gets values of its own, the same on every run, and `uuidV7` takes its time from the test's clock. `Nomi.Crypto` offers the hashes Bun's `CryptoHasher` computes with HMAC too, which leaves BLAKE2s out, and SHA-1 only for protocols that still name it. `Nomi.Password` hashes with argon2id and verifies argon2 and bcrypt, a hash it can't read being a wrong password rather than an error. `Nomi.Compress` is pure for whole values, decompressing to 64 MiB at most, past which a value is a stream's, and a stream's compressor is a reader a task makes, over node:zlib's.

**2026-10-20: routes compose without operators.** `Nomi.Http.Route` reads a path the way elm/url's parser reads a URL, but a package can't define an operator, so segments join with `slash` in a pipeline: `Route.s "todos" |> Route.slash Route.int`. `Nomi.Http.Cookie` parses and serializes cookies as RFC 6265 writes them, in its order of attributes, and signs a value with HMAC-SHA-256 over the cookie's name and value, so a value signed for one cookie isn't taken for another's, verifying in constant time. `Nomi.Http.Form` decodes URL-encoded fields, dropping a field whose escapes aren't UTF-8, and reads a multipart form a part at a time, each part's body a reader made by a task that holds back as many bytes as could start the next boundary, a part left unread being skipped; a form that ends early or names no field fails with the new `BadForm`.

**2026-10-20: a logger is a value.** `Nomi.Log`'s `Logger` holds its least level (`Info` unless `withLevel` says) and its fields, and is passed to what logs as any dependency is, rather than carried by fibers, which architecture §8 gives no FiberRefs; two loggers never share fields, and a fiber logs with the one it was handed. A line goes to the standard error of whatever runs the task, a test's under `nomi test`, in one write, so lines never mix; it is JSON (`time`, `level`, `message`, then the fields, a field named as one of those three written with a `_` before it) unless that standard error is a terminal, where it is text with the level coloured. Its time is the program's clock's, so a test's lines are the same on every run. `Value` is the module's own (`string`, `int`, `float`, `bool`), so nomi/core needs no elm/json.

**2026-10-20: the services run from xtask, on their newest releases.** `cargo xtask services` runs Postgres 18.6, MySQL 9.7 (the newest long-term release), Valkey 9.1 and Garage 2.4.1, each from the multi-platform image references.toml pins by digest, with podman or else docker, and stops them on failure and on SIGINT, SIGTERM or SIGHUP too. MySQL 9 signs in only with caching_sha2_password, whose first sign-in needs TLS or the server's RSA key, and Bun's client takes the key only when asked (`allowPublicKeyRetrieval`), so a MySQL connection without TLS fails until the driver of MB.17 says which it does. CI runs the services with docker, whose daemon GitHub's Linux runners keep.

**2026-10-20: SQL values are constructors, and a transaction holds its database.** nomi/sql 1.0.0's `Value` exposes its constructors, `Int64 String` among them, where D9 of the MB draft named a function, `int64Value`: Elm exposes a type's constructors all or none, so a parameter from decimal text is a constructor too, and the kernel checks its text, as it refuses an `Int` past ±(2^53 − 1), already rounded, and a NaN, which SQLite would store as NULL, each with `BadParameter`. Rows decode by column name as `Json.Decode` reads fields, and `columns` reads a row whose columns a program doesn't know. Errors are typed: `Violated` with the kind of constraint a change broke (unique, foreign key, not null, check), which a program reacts to, and `Failed` with the database's code and message for the rest. SQLite opens with its foreign keys enforced, as Postgres and MySQL enforce theirs. `Bun.sql` reserves no SQLite connection, so a transaction holds the database itself: while it runs, other fibers' statements wait for it, rather than run inside it; one within it is a savepoint; and a finalizer rolls it back once it fails or is interrupted.

**2026-10-20: nomi/sql reaches servers through a pool of its own, and TLS by `sslmode`.** `Nomi.Sql.connect` reaches Postgres and MySQL through the `Net` from a `Config`, a URL (`configFromEnv` reads `DATABASE_URL`). A statement's placeholders are its database's own, `?` on SQLite and MySQL and `$1` on Postgres: rewriting them would mean parsing SQL. The pool is nomi's: it reserves up to its size of `Bun.sql`'s connections and keeps each, so a transaction holds one, a fiber waits for one in nomi's queue, which interruption leaves, a statement gives its connection back once it has run, whether or not its fiber still waits, and a connection that breaks leaves the pool, as Bun's reserved connection fails every statement, with no code, once its server ends it. SQLite is a pool of one. TLS follows libpq's `sslmode`, `prefer` by default, which nomi implements as `require`, then `disable` where the server has no TLS, since Bun's `prefer` waits out a 30-second timeout on a Postgres without it. MySQL 9 takes a password only over TLS, or encrypted with a key the client fetches, which a server in the middle could forge, so nomi never fetches it, and `disable` to MySQL fails saying so. Postgres's and MySQL's 64-bit integers read as `Int` or `Int64` (Bun's `bigint`), any number that is an integer as `Int`, a `numeric` as its text, a time as ISO 8601 text and JSON as its text.

**2026-10-20: a listener fails when its connection is lost.** `Nomi.Sql.listen` listens on a Postgres channel through `Bun.sql`'s `listen`, on a connection of the listener's own. Bun reconnects a listener whose connection was lost and listens again, and what was sent meanwhile is gone without a word; it calls the listener's `onlisten` again as it does, so nomi fails the listener then, with `Unreachable`, for the program to listen anew and catch up from its tables. Bun gives no sign of a connection that stays lost, so until it reconnects the listener waits. A listener holds 1,000 notifications its fibers haven't taken and fails past them with SQLSTATE `54000`; on MySQL and SQLite, which have no channels, `listen` fails with `0A000`.

**2026-10-20: a TCP connection is a pair of streams, owned by a fiber.** nomi/net 1.0.0's `Nomi.Tcp` gives a connection as a `Stream.Reader` and a `Stream.Writer`, so what reads and writes files and bodies reads and writes sockets too: the socket is read only while a read waits, holding its peer back, a write waits until the socket has taken its bytes, and closing the writer ends this side alone, Bun's `shutdown()` (its `shutdown(true)` closes the socket). A connection is the fiber's that made it, and `listen` hands each accepted one to a fiber of its own, as `Nomi.Http.Server` does a request, in the scope of the task listening, so interrupting that task interrupts them and closes their connections. Unix sockets go through `Net` too, and a network narrowed to some hosts reaches none, as none is a host it names. On `Net.loopback`, a server and its clients connect in memory, where a write is taken at once.

**2026-10-20: a TLS connection is made once its server is trusted.** `Nomi.Tls.connect` checks the server's certificate against a `Trust`, the system's authorities or given ones, and for the host connected to. Bun reports a certificate it can't trust in its handshake and leaves the socket open, so nomi waits for the handshake and fails the connection with `Nomi.Tcp.Untrusted`, rather than hand over one any server in the middle could have answered. A socket mid-handshake is read whatever the reads ask, as the handshake reads to go on. `upgrade` and `accept`, a STARTTLS's two sides, make the connection's socket TLS; the plain connection then fails its reads and writes, and ending it ends the secure one. On `Net.loopback`, TLS is a connection in memory like any other, with no certificate to check.

**2026-10-20: UDP binds a client's port freely, and drops as UDP does.** `Nomi.Udp.bind` with port 0 is a client's socket, which a network that may not listen (`Net.noListen`) still binds; a port of its own is listening, which it refuses. A socket holds 1,000 datagrams no `receive` has taken and drops those past them, as a full socket buffer does, rather than fail as an event source past its bound would: losing datagrams is UDP's contract. A datagram goes to an address, so `send` looks a name up first. On `Net.loopback`, a datagram to a port nothing is bound to is dropped, and `Nomi.Dns` resolves this machine's names alone.

**2026-10-20: nomi is its own language.** nomi forks from Elm 0.19 at the tag `elm-compat-final`, the last commit of MB.18b, and is no longer compatible with Elm's compiler, packages or tools. The maintainer wants to see how far Elm's way of programming goes on a server and to make it perform like the best compiled languages there, and every obstacle to that is something compatibility pins down: a JavaScript target with a tracing collector, an `Int` that is a double, UTF-16 strings, four built-in special cases where a type class would do, and an effect system built for the browser. So architecture R1 ("one semantics, many platforms", with no language changes) and R5 (compatibility measured against upstream) are rewritten: a program means what nomi's reference and its reference interpreter say, there is one platform, and backends are tested against the interpreter. The elm, elm-format, elm-language-server and elm-test parity targets, Compat, the oracles, the browser, ports and effect modules all go (plan F1). The name stays nomi, source files end in `.nomi`, and the work continues in this repository, whose history up to the tag is the Elm toolchain. The alternative, a compatible toolchain with a faster backend, would keep every one of those obstacles.

**2026-10-20: MB stops at MB.18b, and MP is superseded.** Redis, S3, the examples' review and release 0.7 were the rest of MB, all built on Bun's built-ins, which F5 replaces with a native runtime; building them on Bun now would be work thrown away. MP measured and tuned a toolchain whose output ran on Bun. Its measurement contract carries over to the scoreboard (plan F2.6), and its candidates either no longer apply or wait for profiles of native code (F6). The tree at `elm-compat-final` is MB.18b, unreleased; 0.6.0 stays the last release of the Elm toolchain. The alternative, releasing 0.7 first, would ship batteries that F5 rewrites, to users the fork leaves anyway.

**2026-10-20: one target, Linux x86-64, as a static executable without libc.** nomi compiles to a static ELF for Linux x86-64 that makes system calls directly: no dynamic loader, no libc, and its own static linker, which needs only the relocations rustc and the backend emit. One operating system and one architecture make each of these bounded work, and together they remove startup cost, a dependency on the deployed system's libraries, and libc's overhead on every I/O call. I/O goes through io_uring, with epoll where io_uring is refused, chosen at startup, since Docker's default seccomp profile refuses io_uring. The alternatives were LLVM, whose build time and size buy little a pure, monomorphized language needs, and several targets at once, which would split every runtime decision before any of them is measured.

**2026-10-20: the reference interpreter is the oracle.** With upstream gone, correctness needs a reference that isn't the code under test. The interpreter runs the typed IR with nomi's semantics; it is checked against the JavaScript backend while that exists (outside a listed table of intended differences), and the native backend is checked against it on every test suite, the examples, the corpus and generated programs, for as long as both exist. It also runs code after reference counting is inserted, in a mode that counts every reference, so leaks and double frees show up before machine code does. The alternative, testing native code against expected outputs alone, would leave every untested program unchecked.

**2026-10-20: memory is reference-counted, per core, with nothing shared.** Values are reference-counted in the style of Perceus: the compiler inserts each `dup` and `drop`, infers borrowed parameters, and reuses a value's memory when its count is one, so pure code updates in place. The runtime runs one scheduler per core, and a fiber and its children stay on their core, so counts are never atomic; a value crossing to another core is copied, or frozen, after which its count is atomic and it is never reused in place, and `Ref` and `Queue` cells belong to one core and are reached from others by message, which tasks already hide. Immutable values can't form cycles, so only those cells could leak one. `unsafe` is allowed in the runtime crate and the emitted code alone (R2). The alternatives were a tracing collector, whose pauses and memory overhead are what a server pays for on the JavaScript target, and atomic counts everywhere, which cost on every pointer copy.

**2026-10-20: machine code through nomi's SSA, Cranelift first.** The backend lowers the monomorphized IR to an SSA of nomi's own and emits it through Cranelift, so that the memory model and the runtime, where most of a functional program's speed is decided, can be measured early. A hand-written x86-64 encoder can replace Cranelift behind the same boundary, if the scoreboard shows code generation is what's slow. The alternative, writing the encoder first, would delay every measurement by the time it takes.

**2026-10-20: type classes replace the four special cases.** `number`, `comparable`, `appendable` and `compappend` become classes, and users can declare their own: one parameter, superclasses, coherence by the orphan rule, and derivations of `Eq`, `Ord`, `Hash`, `Debug`, `Encode` and `Decode`. Nothing is derived implicitly, as an implicit instance would conflict with one a module declares; records and tuples get the compiler's structural instances, which no module can declare. `==` requires `Eq`, so comparing functions is a type error rather than a crash. Programs are monomorphized whole, so dictionaries become direct calls and polymorphic recursion is rejected. As the maintainer chose, a class is declared with `type class`, the way `type alias` declares a record, its body a record of its methods' types (`type class Eq a = { eq : a -> a -> Bool }`, a superclass as `type class Eq a => Ord a`), and an instance with `instance`, its body a record of their definitions (`instance Eq Color = { eq = … }`); an instance with no body is derived (`instance Ord Color`), so a type's instances, written or derived, are all found the same way and no third keyword is needed. Constraints go before `=>` in signatures. A class has no default methods, a function every instance shares being an ordinary function constrained by it. The alternatives were a `deriving` clause on the type, which would have to infer a derived instance's constraints, and default methods, which add a second way to define a function.

**2026-10-20: `Int` is 64-bit and wrapping, `String` is UTF-8.** `Int` is a 64-bit two's complement integer whose arithmetic wraps, the machine's own, and division by zero still gives 0. `String` is UTF-8, its header holding its byte length and whether it is all ASCII. `String.length` and indexes count Unicode scalars, as `String.toList` gives them, in constant time on ASCII text, and `String.byteLength` gives the bytes, as the maintainer agreed. The alternatives were trapping on overflow, which costs a branch on every operation, and lengths in bytes, which make `String.slice` able to cut a character in half.

**2026-10-20: the first stage's library is minimal, and JavaScript goes after the interpreter.** The maintainer wants the native target built on the least surface, so the library shrinks to the basic types (`Basics`, `Bitwise`, `Char`, `String`, `List`, `Maybe`, `Result`, `Tuple`, `Debug`), tasks and fibers, which the runtime is built around, and standard I/O on text, with the program's arguments and exit code (plan F1.7). nomi/http, nomi/net, nomi/sql, the other elm/* packages, `Dict`, `Set` and `Array` go, and the services suite with them; they come back natively, one module at a time, in F5, taking their tests and guarantees from `elm-compat-final` where those still hold. elm-test goes with the browser it depends on, and the language's tests become programs checked by their output, which every backend runs alike. With the library that small, the JavaScript backend is worth keeping only to check the interpreter, so it goes at the end of F2 rather than after the native platform, and classes (F3) are built for the interpreter and native code alone. The alternative, keeping the Bun platform until native code replaced it, would carry every package through the change to `.nomi`, nomi.toml and classes, only to rewrite it.

**2026-10-21: library modules have no prefix.** nomi's modules were `Nomi.Stdio`, `Nomi.Fiber`, `Nomi.Http.Server` and so on, so as not to collide with Elm's packages, which nomi's programs used beside them. nomi now has one standard library of its own, so, as the maintainer asked, its modules are named for what they are: `Program`, `Stdio`, `Fiber`, and later `Bytes`, `Json`, `Http.Server`. What `Nomi.Task` added to elm/core's `Task` belongs to `Task`, and `main : Program`, its type imported by default as Elm imported `Platform.Program`. Packages keep the `nomi/` owner, the library being nomi/core. The alternative, keeping the prefix, would mark nomi's modules as additions to a library that no longer exists.
